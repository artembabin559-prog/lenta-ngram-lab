# Тема 11. Биграммы против триграмм в генерации

## Что требует задание

Вариант 11 находится на с. 3 файла «Темы для второго блока.pdf». Он рассчитан на 3–4 человек. Обе модели обучаются на одном корпусе минимум из 300 предложений. Каждая создаёт 30 текстов при одинаковых ограничениях длины. Нужно сравнить повторяемость, долю корректных завершений и связность по заранее выбранной шкале. Вывод должен ответить на три вопроса. Какая модель чаще воспроизводит фразы корпуса? Как меняется связность при переходе от биграмм к триграммам? Что происходит в редких контекстах?

## Опора на материалы курса

| Материал | Что используется |
|---|---|
| «Инструменты для предобработки текста», страницы PDF 3–4 | Токенизаторы NLTK для случая, когда в источнике отсутствует готовое разбиение. |
| «Моделирование языка», с. 8–15, 19 | Условные вероятности из частот, контекст N-граммы, проблема ненаблюдавшихся переходов, влияние размера корпуса. |
| «Генерация текста», с. 18–19, 38, 42 | Пошаговый выбор следующего слова по частотам, повторы и короткая память модели, содержательная оценка связности. |
| Архив «3. samples (5).zip» | Скрипт `l3s1_class_demo.py` классифицирует 30 коротких фрагментов по стилометрическим признакам. Готового корпуса или генератора для варианта 11 в архиве нет. |

## Выбранный источник

Корпус состоит из 500 предложений рубрики «Спорт» Lenta.ru. Источник — [архив новостей версии 1.1](https://github.com/yutkin/Lenta.Ru-News-Dataset/releases/tag/v1.1). Адрес статьи для каждого предложения сохранён в `corpus.jsonl`.

## Рабочие решения до эксперимента

1. **Корпус.** Подготовить единый набор из 500 русскоязычных предложений одного жанра. Зафиксировать версию источника и порядок отбора. Убрать заголовки, пустые записи и точные дубликаты, оставить предложения с конечным знаком. Сохранить словоформы, пунктуацию и для каждого примера идентификатор документа и номер предложения. Проверить размер итоговой выборки после очистки.
2. **Модели.** Реализовать на Python подсчёт продолжений для контекста из одного токена для биграмм и двух токенов для триграмм. Границы каждого предложения обозначить служебными маркерами. Переходы между соседними предложениями не учитывать. В обеих моделях выбирать продолжение случайно с весом, равным его частоте. Для базового сравнения использовать только наблюдавшиеся переходы.
3. **Генерация.** Один текст — одна попытка сгенерировать предложение от начального маркера до конечного, максимум 30 слов. Пунктуацию и маркеры в длину не включать. После 30-го слова разрешить закрывающую пунктуацию и маркер конца. Если модель выбирает 31-е слово, сохранить первые 30 и отметить обрыв. До запуска зафиксировать одинаковый список из 30 значений `seed` для обеих моделей. Сохранить все 60 результатов, включая короткие, повторные и оборванные, вместе с параметрами и причиной остановки.
4. **Оценка.** Применить правила из таблицы ниже. Для оценки связности перемешать все 60 текстов и скрыть названия моделей. Сначала сохранить оценку каждого текста и краткое объяснение спорных случаев, затем раскрыть модель. Показать абсолютные числа вместе с долями и распределение баллов по каждой модели.
5. **Разбор редких контекстов.** Редким считать контекст, который встретился в корпусе один или два раза. Для выбранного примера выписать контекст, наблюдавшиеся продолжения с частотами, фактический выбор и его последствие. Проверить, воспроизводит ли цепочка однозначных переходов длинный отрывок источника. При генерации от штатного начала по наблюдавшимся переходам редкость сама по себе не приводит к отсутствию продолжения. Не приписывать модели сбой, которого нет в результатах.
6. **Материалы для сдачи.** Подготовить запускаемый Python-проект с командой воспроизведения, корпусом и таблицей всех результатов. В отчёте описать данные, алгоритм и протокол оценки, привести сводную таблицу, характерные примеры и ответы на три вопроса задания. Для презентации выбрать один наглядный переход модели, по примеру от каждой модели, основные показатели и разбор редкого контекста. Количественные выводы перенести из одного и того же прогона.

## Правила оценки

| Показатель | Как считать |
|---|---|
| Повтор фразы из корпуса | Для каждого текста проверить, есть ли в нём последовательность из 4 соседних слов, дословно встретившаяся внутри одного предложения корпуса. Сравнивать без учёта регистра и пунктуации. Основной показатель — число текстов с таким совпадением из 30. Дополнительно указать, сколько текстов совпало с исходным предложением целиком. |
| Внутренний повтор | Число текстов из 30, в которых одна и та же пара соседних слов встретилась хотя бы дважды. Помогает отличить зацикливание от воспроизведения источника. |
| Корректное завершение | Число текстов из 30, где модель дошла до маркера конца, а последняя конструкция синтаксически завершена. Например, обрыв после предлога не засчитывается. Причину остановки берём из программы, завершённость конструкции проверяем при чтении. |
| Связность | 0 — смысл целого восстановить не удаётся. 1 — понятны отдельные фрагменты, но между ними есть смысловой разрыв. 2 — высказывание выражает одну понятную мысль, связи между его частями прослеживаются. Для каждой модели показать количество оценок 0, 1, 2 и средний балл. |

## Журнал выполнения

1. Проверены формулировка темы и лекции. В приложениях отсутствуют готовый корпус для генерации и обязательный шаблон отчёта. Для очистки использованы токенизаторы NLTK, для самого генератора — стандартная библиотека Python.
2. Из выпуска v1.1 отобраны первые 500 подходящих предложений рубрики «Спорт», до пяти из каждой статьи. При проверке работы русского Punkt выявлены склейки соседних предложений. Добавлен фильтр внутренних конечных знаков и полностью повторены отбор данных, генерация и оценка. Фильтр консервативен и иногда отбрасывает фразы с сокращениями.
3. Финальная выборка содержит 500 предложений из 102 статей за 17.02–27.03.2000. В ней 8 558 слов и числовых токенов. Регистр учитывается при обучении, а при поиске повторов игнорируется. Даты определены по URL публикаций.
4. По окончании очистки сохранены все 60 попыток. Перемешанные тексты оценил один ИИ-разметчик без названий моделей и причин остановки. В ratings.csv записаны отдельные оценки и пояснения. Факты о командах и спортсменах не проверялись.
5. Для каждого ответа сохранены выбранные продолжения и частоты. По ним проверены примеры T03, T35, T40 и T45, использованные в отчёте. По тем же итоговым данным составлена презентация.

## Примеры для защиты

- **T03 и T40.** При одинаковом seed 3 обе модели начали со слов «Матч в». Биграмма выбирала среди 247 продолжений после «в». Триграмма знала единственное продолжение после «Матч в» и воспроизвела предложение S436 целиком. [Новость о матче](https://lenta.ru/news/2000/03/22/porto/).
- **T35.** После придаточного союза в контексте «, которая» встретились пять вариантов. Триграмма соединила причину пропуска футбольного матча со временем биатлонистки. Исходные предложения S117 и S093 можно найти по их ID в корпусе. [Футбол](https://lenta.ru/news/2000/02/23/soccer/) и [биатлон](https://lenta.ru/news/2000/02/22/biatlon/).
- **T45.** Биграмма выбрала кавычку, точку и EOS. Остановка штатная, но слов в ответе нет. Пример объясняет разницу между остановкой и качеством окончания.

Выводы относятся к одной исторической выборке, двум наборам по 30 текстов и оценкам одного разметчика. Для повторного запуска из папки проекта выполните `python experiment.py` (Python 3.10 или новее). Бланк для собственной оценки создаёт команда `python experiment.py --blind --out review`. После заполнения `review/blind.csv` пересчитайте результаты командой `python experiment.py --ratings review/blind.csv --out reviewed`.

## Повторный сбор корпуса

Для основного запуска данные уже включены. Если нужен повторный отбор из исходного архива, скачайте `lenta-ru-news.csv.bz2` из [выпуска v1.1 архива Lenta.Ru-News-Dataset](https://github.com/yutkin/Lenta.Ru-News-Dataset/releases/tag/v1.1) и установите NLTK с проверенной версией.

```console
python -m pip install nltk==3.10.4
python -m nltk.downloader punkt_tab
python prepare_corpus.py lenta-ru-news.csv.bz2 --out rebuilt.jsonl
```

Архив читается в исходном порядке. Фильтр оставляет точное значение рубрики «Спорт». Из тела каждой уникальной статьи берётся до пяти первых подходящих предложений. Токенизатор предложений — русский Punkt, токенизатор слов — RegexpTokenizer из NLTK. Правило токенизации записано в `prepare_corpus.py`. Порог — четыре слова или числовых токена и хотя бы одна русская буква. Заголовки, HTML, ссылки, неоднозначные внутренние точки и другие внутренние конечные знаки отсекаются. Дубли определяются после удаления пунктуации и приведения к нижнему регистру. Набор закрывается на 500-м предложении. Это последовательная историческая выборка за 17 февраля — 27 марта 2000 года.

SHA-256 итогового `corpus.jsonl` — `b49b6c087d0c65de19c291b462224705a1a23001488cb682e6477b6d962a3d3d`. SHA-256 использованного архива данных NLTK `punkt_tab.zip` — `e57f64187974277726a3417ca6f181ec5403676c717672eef6a748a7b20e0106`. Ссылки на публикации Lenta.ru сохранены для каждого предложения.
